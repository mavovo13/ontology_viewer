# 技術仕様書 (Architecture Design Document)

## テクノロジースタック

### 言語・ランタイム

| 技術 | バージョン | 備考 |
|------|-----------|------|
| HTML | 5 | セマンティックマークアップ |
| CSS | 3 | CSS Variables・Flexbox・Grid |
| JavaScript | ES2020+ (Vanilla) | フレームワークなし |

Node.js / TypeScript / ビルドツールは使用しない。HTMLファイルをブラウザで直接開いて動作することが要件であるため、コンパイルステップは一切不要。

### フレームワーク・ライブラリ（CDN経由）

| 技術 | バージョン | 用途 | 選定理由 |
|------|-----------|------|----------|
| Cytoscape.js | 3.x (latest stable) | グラフ描画エンジン | 大規模グラフの安定した描画・豊富なAPI・活発なメンテナンス。vis-network（Canvas日本語問題）・d3-hierarchy（自前実装量大）・dagre-d3（メンテ停止）を比較検討の上で選定 |
| cytoscape-elk | 2.x (latest stable) | ELKレイアウトエンジン | LAYEREDアルゴリズムによるISA継承ツリーの高品質な自動レイアウト。ELKはJava由来のプロジェクトで、階層グラフレイアウトの精度が高い |
| Google Fonts | - | Webフォント（JetBrains Mono / VT323 / Major Mono Display） | CDN経由で読み込み。ビルドステップ不要 |

### 開発ツール

| 技術 | 用途 |
|------|------|

## アーキテクチャパターン

### フロントエンド単層アーキテクチャ

本プロジェクトはサーバーを持たないブラウザ完結型アプリケーションのため、
従来の3層アーキテクチャではなく、フロントエンド内の関心事分離で設計する。

```
┌────────────────────────────────────────────────┐
│   Presentation Layer（UIコンポーネント）                    │
│   FileUploader / ThemeSwitcher / ViewToggle / SidePanel   │
├────────────────────────────────────────────────┤
│   Logic Layer（ビジネスロジック）                 │
│   XMLParser / GraphBuilder                      │
├────────────────────────────────────────────────┤
│   State Layer（状態管理）                        │
│   AppState（シングルトン・オブザーバーパターン）   │
├────────────────────────────────────────────────┤
│   Rendering Layer（グラフ描画）                  │
│   W_CONCEPTSView / R_CONCEPTSView               │
│   （Cytoscape.js + cytoscape-elk）              │
└────────────────────────────────────────────────┘
         ↑
    ブラウザAPI（DOMParser / FileReader / File API）
```

#### Presentation Layer
- **責務**: ユーザーイベントの受付、状態変化の反映、UI制御
- **許可**: Logic Layer の呼び出し、State Layer の更新
- **禁止**: グラフ描画ロジックの直接記述、XMLパース処理
- **例外**: `ThemeSwitcher` はAppStateに依存せず、localStorageで独立した状態管理を行う

#### Logic Layer
- **責務**: XMLパース・グラフデータ構築などのビジネスロジック
- **許可**: ブラウザAPIの呼び出し、State Layer への書き込み
- **禁止**: DOM操作、直接のUI更新

#### State Layer
- **責務**: アプリ状態の一元管理とイベント通知（オブザーバーパターン）
- **許可**: 状態の読み書き、サブスクライバーへの通知
- **禁止**: DOM操作、ビジネスロジックの実装

#### Rendering Layer
- **責務**: Cytoscape.js を用いたグラフ描画のみ
- **許可**: State Layer の読み取り、Cytoscape API の呼び出し
- **禁止**: XMLパース処理、UIイベントの直接バインド

## データ永続化戦略

本アプリケーションはデータを永続化しない。
XMLファイルはブラウザセッション内のみでインメモリ処理され、ページリロードで消去される。

| データ種別 | ストレージ | 理由 |
|-----------|----------|------|
| パース済みオントロジーデータ | JavaScriptメモリ（AppState） | サーバー送信なし・ページリロードで消去 |
| 選択状態・アクティブビュー | JavaScriptメモリ（AppState） | 揮発性で問題なし |

## パフォーマンス要件

### レスポンスタイム

| 操作 | 目標時間 | 測定方法 |
|------|---------|---------|
| ファイルドロップ → 初期グラフ表示 | 10秒以内 | `performance.now()` でドロップイベントから `cy.ready()` まで |
| ビュー切り替え（W⇔R） | 500ms以内 | トグルクリックから描画完了まで |
| ノードクリック → サイドパネル更新 | 100ms以内 | `tap` イベントから DOM更新まで |

### リソース使用量

| リソース | 目安 | 備考 |
|---------|------|------|
| メモリ | 500MB以下 | 標準規模のオントロジーXML |
| JavaScript Heap | 200MB以下 | Cytoscape.js インスタンス含む |

## セキュリティアーキテクチャ

### データ保護

- **ローカル処理徹底**: XMLファイルはブラウザの `FileReader` API のみで処理し、外部サーバーへの送信は行わない
- **外部通信**: CDNからのライブラリ読み込みのみ（ユーザーデータの送信ゼロ）

### 入力検証

- **ファイル形式チェック**: MIME typeが `application/xml` または拡張子 `.xml` であることを確認
- **XMLパースエラー**: `DOMParser` のパースエラーを捕捉し、ユーザーにメッセージ表示
- **最大ファイルサイズ**: 100MB を超える場合は警告表示（P2: Web Worker対応まではUIフリーズのリスク）

### XSS対策

- **DOM操作**: オントロジーファイルから取得したテキストは必ず `textContent` または `createTextNode` でDOMに挿入
- **innerHTML 使用禁止**: 動的コンテンツへの `innerHTML` 直接代入は禁止。テンプレート展開が必要な場合は `document.createElement` + `textContent` を使用
- **Cytoscape ラベル**: ノードラベルはCytoscapeの `label` プロパティ経由で設定（Canvas描画のためXSS不要）

## スケーラビリティ設計

### データ増加への対応

| 想定規模 | 概念数 | 対応方針 |
|---------|--------|---------|
| 小規模 | 〜500概念 | 全件表示 |
| 中規模 | 500〜2000概念 | 初期表示は全件、P1でフィルタ機能で絞り込み |
| 大規模 | 2000概念〜 | P2でWeb Worker分離処理・Virtual rendering検討 |

### 機能拡張性

- **新ビューの追加**: `src/js/views/` ディレクトリに新クラスを追加し、`ViewToggle` にオプション追加
- **XMLフォーマット拡張**: `XMLParser` クラスのメソッドを追加することで対応
- **レイアウトアルゴリズム変更**: Cytoscape-elk のアルゴリズム設定を変更するだけで切り替え可能

## テスト戦略

本プロジェクトはバニラJS・フレームワークなし構成のため、初期フェーズはブラウザ手動テストを中心とする。

### 手動テスト（初期フェーズ）

| テスト項目 | 確認方法 |
|-----------|---------|
| XMLアップロード → グラフ表示 | 実際のXMLファイルをドロップして目視確認 |
| W_CONCEPTS / R_CONCEPTS ビュー切り替え | トグル操作で表示が正しく切り替わることを確認 |
| ノードクリック → サイドパネル | 全主要ノードをクリックして詳細が正しく表示されることを確認 |
| 不正XMLのエラーハンドリング | 非XML・空ファイル・不正フォーマットXMLでエラー表示を確認 |

### ユニットテスト（P1: XMLParserの品質保証）

- **対象**: `XMLParser.js` のパースロジック
- **方法**: ブラウザ上で実行可能な軽量テストランナー（例: `jasmine` CDN経由）、またはシンプルなアサーション関数
- **カバレッジ目標**: XMLParser の正常系・異常系パスを網羅

## 技術的制約

### 環境要件

- **対応ブラウザ**: 初期スコープは Chromium系ブラウザ（Chrome / Edge）最新版
  - Firefox / Safari は初期スコープ外（`cytoscape-elk` のWeb Worker動作が未検証）
- **実行環境**: ローカルファイルシステムからHTMLを直接開いて動作
- **外部依存（CDN）**: Cytoscape.js・cytoscape-elk の読み込みにはインターネット接続が必要
  - オフライン対応が必要な場合はライブラリをローカルに同梱すること

### パフォーマンス制約

- **ELKレイアウト計算**: 大規模グラフ（2000ノード以上）では初期レイアウト計算に数十秒かかる可能性がある（P2でWeb Worker対応）
- **シングルスレッド**: バニラJSのため、P2実装前はXMLパース中はUIがフリーズする場合がある

### セキュリティ制約

- **CORS**: 外部URLからのXML読み込み（P2機能）は CORS 制約を受ける。`fetch` API で対応するが、対象サーバーが `Access-Control-Allow-Origin` を設定している必要がある

## 依存関係管理

CDN経由で読み込むライブラリのバージョン管理方針:

| ライブラリ | CDN URL パターン | バージョン管理方針 |
|-----------|----------------|-------------------|
| Cytoscape.js | `unpkg.com/cytoscape@3.x.x/dist/cytoscape.min.js` | マイナーバージョンを固定（例: `3.31.0`） |
| cytoscape-elk | `unpkg.com/cytoscape-elk@2.x.x/cytoscape-elk.js` | マイナーバージョンを固定（例: `2.2.0`） |

**方針**:
- パッチバージョンは手動で更新確認してから変更
- メジャーバージョンアップは破壊的変更を確認してから対応
- `latest` や `^` 形式のCDN URLは使用しない（リリースによる意図しない動作変更を防ぐ）
